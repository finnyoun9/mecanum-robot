# 3S 电池供电方案（当前实装基准）

**状态：2026-08-22 写入，2026-08-22 当天修正。** 电机（JGA25-370）**标称 12V**，
不是 6V。之前这份文档把"首次上电用限流电源保守测试的 6V"误写成了"电机的正式工作
电压"，导致以为要单独买一块 6V/≥8A 电机 buck + 第三块 Mini560。**这个结论不成立，
不需要买额外的电机稳压模块。**

`firmware/Core/HW/README.md` 记录的四轮开环测试确实是在 6V 限流电源下做的——这是
第一次通电验证接线时的标准审慎做法（先用限流电源、低电压，确认方向/极性都对了再
上正常电压），不是说明电机只能工作在 6V。TB6612 的 `VM` **应当直接接 3S 电池**
（11.1–12.6V），回到本文档取代前 `docs/wiring.md` 里的原方案，见下方"电源拓扑"。

当前电池为 3S LiPo（3500 mAh）：标称 11.1 V、满电 12.6 V。白色平衡插头测得约
3 V / 7 V / 11 V 是正常的分段电压；它只接平衡充电器或低压报警器，**绝不接负载**。

## 目标拓扑

TB6612 的 `VM` 直接接 3S 电池总线（11.1–12.6V），不需要额外的电机专用稳压模块。
两块 Mini560 按原计划分工：一块给 Pi5+LD06，一块给 STM32+传感器。

```text
3S LiPo XT60
  │
  ├─ 10 A 刀片保险丝（红线，靠近电池）
  ├─ 总开关（12 V DC，额定至少 10 A）
  └─ 配电端子 / 分线排
      ├─ 电机总线：3S 直连（11.1–12.6 V），电机标称 12V，不需要降压
      │   ├─ TB6612 #1 VM（FL + FR）
      │   └─ TB6612 #2 VM（RL + RR）
      ├─ Mini560 #1：3S → 5.00 V
      │   └─ Blue Pill `5V` / `GND`
      └─ Mini560 #2：3S → 5.1 V
          └─ Raspberry Pi 5 GPIO `5V` / `GND` + LD06 激光雷达
```

三路输出的 **GND 必须共地**；三路的正极绝不相连。TB6612 的 `VCC` 由 Blue Pill 的
3.3 V 提供，`VM` 直接接 3S 电池总线，两者不能接反。

## 两块 Mini560 的分工

沿用最早的方案，两块 Mini560 都用不到电机上：

```text
分线排 ── Mini560 #1（调到 5.00 V）── Blue Pill 5V/GND
       └─ Mini560 #2（调到 5.10 V）── Pi 5 GPIO 5V/GND + LD06
```

电机启动/堵转时电机总线（3S 直连）会有噪声尖峰，这也是两块 Mini560 分开给 Pi 和
STM32供电、而不是一块共用的原因——避免电机噪声通过共用稳压模块耦合到两个负载上。

## 选型与布线

| 位置 | 要求 |
| --- | --- |
| 电机支路 | TB6612 `VM/GND` 直接接电池分线，覆盖 3S 全电压范围（11.1–12.6 V），无需额外降压 |
| STM32 Mini560 | 输入接电池分线；输出调为 5.00 V，接 Blue Pill `5V/GND` |
| Pi Mini560 | 输入接电池分线；输出调为 5.10 V（补偿线损），接 Pi 5 GPIO `5V/GND` |
| 主线 | XT60、保险丝、开关、配电端子使用 14–16 AWG 硅胶线 |
| 电机支路走线 | 电池到 TB6612 `VM/GND` 使用 18–20 AWG；不用面包板轨或杜邦线承担电机电流 |
| 滤波 | 每块 TB6612 的 `VM/GND` 旁并联 1000 uF、耐压 >= 16 V 的电解电容，吸收堵转尖峰 |

电池接口使用 XT60 公头线（与电池实际插座配对）。保险丝只串红线；黑线从电池负极直接
回到配电端子的公共 GND。线束用焊接或压接端子加热缩管固定，不能只靠裸线和胶带。

## 首次上电步骤

1. 电池接入前，检查正负极和电容极性；测量 `VM` 与 `GND` 不应短路。
2. 电池先不接，两块 Mini560 只接输入（用可调电源代替电池亦可），万用表把输出调准：
   5.00 V 和 5.10 V。
3. 断电后再接负载。先上 STM32 和 Pi（不接电机），再空载测试单个电机，最后四轮测试。
4. **电机首次通电建议先用限流电源、限流值调低（例如之前验证接线用的 6V/限流档）**，
   确认方向、极性都对了，再换回电池直连的满电压——这是测试步骤上的审慎做法，不是说
   电机的正常工作电压是 6V。
5. 使用 3S 平衡充和 LiPo 防火袋；低压报警建议设在 3.5 V/节，静置后不应低于 3.3 V/节。

调试时 ST-Link 只接 `SWDIO`、`SWCLK`、`GND`；不要用 ST-Link 的 3.3 V 线给已由电池
供电的目标板反向供电。

## 故障记录：AMS1117 击穿 → 4.8 V 灌入 MCU（2026-08-25）

一块 Blue Pill 报废。记下来是因为**这种故障在 3.3 V 供电下完全没有症状**，不知道就会反复踩。

### 现象链

| 时间 | 供电方式 | 现象 |
| --- | --- | --- |
| 上午 | ST-Link 3.3 V → `3V3` 脚 | **一切正常**，反复烧录、跑完两次占空比扫描 |
| 切换后 | 电池 5 V → `5V` 脚 | SWD 完全连不上（`chipid 0x000`） |
| 换回 | ST-Link 3.3 V | 又正常了 |
| 再切 | 电池 5 V | 万用表量 `3V3` 脚：**4.8 V** |
| 之后 | 无论哪种供电 | 内核不再执行代码，反复复位（`S_RESET_ST=1`），烧录失败 |

### 根因

**板载 AMS1117 稳压器内部击穿短路，输入输出直通。** 5 V 接在**正确的** `5V` 脚上，却被短路的稳压器直接送到 3.3 V 轨，MCU 挨了 4.8 V（STM32F103 的 VDD 绝对最大值是 4.0 V）。

**不是接线插错。** 排查时一度怀疑是把 5 V 插到了 `3V3` 那一排，实测证明不是。

### 为什么拖到今天才暴露（关键）

更早之前 Mini560 烧毁那次，很可能同时打穿了 AMS1117。但从那以后调试一直用 **ST-Link 3.3 V 供电**，**再没用过板子的 5 V 输入**——而短路的稳压器在这种接法下就是一根导线，MCU 看到的仍是正常 3.3 V，**毫无症状**。直到今天第一次改回电池 5 V 供电，故障才显现。

> 一个坏了的稳压器可以潜伏数周不被发现，只要你一直从它的输出端供电。

### 30 秒自检法（每次换板子、每次改供电都先做）

在**接任何编码器、TB6612 之前**，单独测这块板：

1. 只给 `5V` 脚喂 5 V，其他全不接 → 量 `3V3` 脚，**必须是 3.3 V**。读到 4.8 V 就是稳压器击穿，立刻断电。
2. 反过来只给 `3V3` 脚喂 3.3 V → 量 `5V` 脚，**应接近 0 V**。如果也读到 3.3 V，说明输出倒灌回输入，同样是击穿。

第 2 条是这次定位问题的决定性测量。

### 附带的判据：flash 容量读数

`st-info --probe` 报告的 flash 容量可以当作**芯片健康度的旁证**：

- 坏板子：`262144` / `67107840` / `25165824` / `24576 KiB` —— 每次都不同且全错
- 好板子：`65536`（64 KiB）—— 三次读数完全一致，数值正确

连 flash 容量寄存器都读不稳，说明芯片本身已经不可靠，不要再浪费时间怀疑杜邦线。

### 预防

- **绝不让两路电源同时喂 Blue Pill**（`5V` 脚和 `3V3` 脚各接一路是最典型的杀法）。切换供电方案时先断再接。
- **给编码器减负**：4 个霍尔编码器 + 2 块 TB6612 逻辑电源全挂在板载 AMS1117 上，对这颗小稳压器是长期满载。建议改由 Mini560 单独供。
- **保险丝**：本文档采购清单里的 10 A 刀片保险丝**至今未装**。3S LiPo 没有限流，短路时可输出上百安培——这次只烧了一块十几块钱的板子，下次未必。
