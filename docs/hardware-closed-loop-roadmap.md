# 真机闭环与 PID 调试路线

> 基线：2026-08-13，2026-08-22 更新真机开环状态。当前 ROS 2、协议、运动学和 SIL 已跑通；主控已确认为 **STM32F103C8T6**，接线方案见 [docs/wiring.md](wiring.md)，供电方案见 [docs/power-system.md](power-system.md)。ST-Link 已连接真机并跑通 PC13 bring-up、四路 PWM/方向/STBY 映射和四轮开环演示，验证记录与可复现构建命令见 [`firmware/Core/HW/README.md`](../firmware/Core/HW/README.md)。这不等于完整 FreeRTOS 机器人固件已真机验证：PID/编码器/协议还没有对应的真机外设初始化（MSP），真实底盘尚未形成编码器速度闭环。

## 项目边界

- `mecanum-robot` 是机器人主项目：树莓派 5 + ROS 2 + STM32 底盘 + 后续机械臂。
- `stm32-pid-balancer` 保留为控制算法实验台，不把“自平衡车”整套并入麦轮车。
- 可复用内容：通用 PID、抗积分饱和、UART 遥测、CSV 日志、阶跃响应分析和调参工具。
- 不直接复用内容：倒立摆直立环、平衡车机械模型和双轮输出混合。

复用前先修两处代码：`stm32-pid-balancer` back-calculation 必须在除以 `Kp` 前判断零值；`mecanum-robot` 的 D 项实现是误差差分，与“derivative on measurement”注释不一致。当前速度环先使用 PI（`Kd=0`），并为这两条边界增加 host test。

麦轮车需要的是四路电机速度 PI；自平衡车需要角度 PD + 速度 PI + 转向环，控制对象和安全风险都不同。

3. ~~测量各占空比下的稳态转速，得到死区和近似 `PWM -> rad/s` 曲线~~ —— 已完成，见下方"占空比 → 转速实测曲线"。
4. 连续记录时间戳、目标速度、实测速度、PWM 和编码器增量。

换算基准已实测（2026-08-23）：手动转右前轮 10 圈两次，计数 2240 / 2244，即 **224 edges/圈**（`firmware/Core/HW/encoder_count_main.c`，两次相差 0.18%）。轮径 60 mm 实物确认，半径 0.030 m。

原先 `encoder.h` 的推导值 `11 × 4 × 34 = 1496` 错了 6.7 倍，两个原因叠加：减速比实际约 1:20 不是 1:34（224 ÷ 11 ≈ 20.4），且软件 EXTI 解码只数上升沿（1 倍频），不是硬件正交的 4 倍频。里程计直接按这个数缩放，用错等于距离读数差同样倍数。已同步修正三处：`encoder.h`、ROS 2 硬件接口 `mcr_hardware_interface.cpp`、协议模拟器 `tools/stm32_uart_sim.py`；轮径同步修正 URDF 和 `controllers.yaml`（原按 65 mm）。

### 占空比 → 转速实测曲线（2026-08-23）

抬起底盘，`firmware/Core/HW/duty_sweep_main.c` 逐级驱动四轮，每级稳定 300 ms 后测 1 秒窗口内的编码增量。下表为四轮平均，按 224 edges/圈换算：

| 占空比 | edges/s | rev/s | rad/s | m/s |
|---|---|---|---|---|
| 5% | **0** | 0 | 0 | 0 |
| 10% | 71.5 | 0.32 | 2.01 | 0.060 |
| 15% | 120 | 0.54 | 3.37 | 0.101 |
| 20% | 169 | 0.75 | 4.73 | 0.142 |
| 30% | 267 | 1.19 | 7.49 | 0.225 |
| 40% | 366 | 1.63 | 10.25 | 0.308 |
| 50% | 464 | 2.07 | 13.02 | 0.391 |
| 60% | 563 | 2.51 | 15.79 | 0.474 |
| 70% | 662 | 2.96 | 18.57 | 0.557 |
| 80% | 760 | 3.39 | 21.32 | 0.640 |

**线性度**：20% 以上斜率稳定在约 **0.986 edges/(duty·s)**，每加 10% 占空比增加约 99 edges/s，接近理想直线——被控对象线性，PID 不需要增益调度。

**死区**：5% 时四轮完全不转，10% 正常。线性段向下外推交于占空比约 **3%**，但实测 5% 起不来——差值来自静摩擦，**启动死区（5%~10% 之间）高于线性外推死区**，PID 前馈/抗积分饱和要按启动死区处理。死区具体位置未做更细分辨率的测量。

**四轮一致性**：80% 时 RL 最快 771、RR 最慢 750，差 2.8%；各轮斜率 0.973~1.000。差异小，四路 PID 可先用同一组参数起步。

**外推满占空比**：约 4.27 rev/s ≈ **0.81 m/s** 车速上限（SIL 的 `max_wheel_rps` 已按此更新）。

⚠️ **该曲线绑定当时的供电电压**（DP100 台面供电，非电池）。转速与供电电压近似成正比，换成 3S 电池（11.1–12.6 V，且随电量下降）后曲线会整体平移，上车后需复测。

**仍未实测**：带载（落地）转速、堵转电流、阶跃响应。

通过条件：正向 PWM 对应正向转速；重复三次的稳态转速偏差可解释；堵转能立即停机。

## M2：单轮速度 PI

先关闭 D，仅调速度 PI：

1. `Ki=0`，逐步提高 `Kp`，直到响应足够快但不持续振荡。
2. 从小值加入 `Ki`，消除负载下稳态误差；启用输出限幅和抗积分饱和。
3. 对 5、10、15 rad/s 做阶跃，计算上升时间、超调、稳态误差、IAE。
4. 控制周期固定为 100 Hz，记录实际周期 jitter；禁止用日志输出阻塞控制任务。

通过条件：三档速度均稳定，结果有 CSV 和曲线；参数不是“感觉差不多”，而是有指标可比较。

## M3：四轮闭环

1. 四个电机分别测死区和增益，不默认四路参数完全一致。
2. 测试前进、横移、原地旋转时四轮目标符号和实际方向。
3. 空载后再落地测试，观察电池电压、轮胎打滑和机械装配误差。
4. 加入通信失联、编码器无跳变和超速保护。

通过条件：四轮闭环持续 30 min 无失控；三种基本运动均可重复；急停和 100 ms 通信超时有效。

## M4：Pi 5 + STM32 HIL

1. Pi 5 发送 `/cmd_vel`，通过共享协议下发四轮目标速度。
2. STM32 回传编码器/轮速；ROS 2 硬件接口发布真实 joint state 和 odometry。
3. 对比协议模拟器与真机日志，修正轮径、轮距、编码器比例和方向。
4. 录制前进 1 m、横移 1 m、原地 360° 三项测试，报告位置/角度误差。

通过条件：链路从 `/cmd_vel` 到真实 PWM、再从编码器回到 `/odom` 闭合；不再把协议模拟器数据写成真机结果。

## PID 难度判断

| 内容 | 预计难度 | 建议投入 |
|---|---|---|
| 单电机速度 PI | 中等，硬件正常后 1–2 天可见结果 | 当前优先 |
| 四轮速度闭环 | 中等偏高，主要难在一致性、电源和方向 | 当前主线 |
| 位置环 | 中等，可作为控制实验 | 非求职必需 |
| 自平衡串级 PID | 高，机械重心、IMU 零偏、周期抖动和电源都会影响 | 求职后或底盘完成后再做 |
