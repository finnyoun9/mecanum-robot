# 接线与引脚分配指南

本文档描述麦克纳姆轮机器人的完整接线拓扑、STM32 定时器分配策略和 Raspberry Pi 5 连接。

**主控已确认为 STM32F103C8T6（Blue Pill）**，驱动板为 2 块裸露引脚 TB6612（AIN1/AIN2/BIN1/BIN2/PWMA/PWMB/STBY 分开引出），IMU 为 MPU6050。下方"已确认引脚分配"是按这套实际硬件核对过冲突的最终方案；再往下的 TIM 分配方案历史章节是硬件选型阶段针对 STM32F407VET6 候选板写的，仅作参考，**不要按那套接**。

> **供电请以 [3S 电池供电方案](power-system.md) 为准。** 电机（JGA25-370）标称 12V，TB6612 的 `VM` 直接接 3S 电池总线（11.1–12.6V），不需要额外的电机降压模块——这和本文后面"12 V 总线直连 VM / Mini560 供 Pi"这段旧草案的结论一致，只是电压细节以 power-system.md 为准。（2026-08-22 一度错误地把首次通电测试用的 6V 限流电源电压当成了电机的正式工作电压，已在 power-system.md 中修正。）

### 细节连接说明

**电机供电链路：**
- 12V 总线 → TB6612 #1 VM + TB6612 #2 VM （各配 1000μF 电解电容并联滤波）
- TB6612 逻辑电源 (VCC) → STM32 板载 3.3V LDO 输出 **（不要接 5V，防止 GPIO 烧毁）**
- TB6612 #1: 控制电机 FL + FR (2个通道)
- TB6612 #2: 控制电机 RL + RR (2个通道)

**信号连接：**
- STM32 GPIO (DIR) → TB6612 方向控制引脚 (A, B)
- STM32 TIM PWM → TB6612 PWM 使能引脚 (PWMA, PWMB)
- STM32 TIM 编码器模式 → 电机编码器 (A, B 相位)
- STM32 I2C1 → MPU6050 (SCL, SDA)
- STM32 I2C2 → VL53L0X (SCL, SDA)（可选：某些 ToF 模块支持 UART，但 I2C 更常见）
- STM32 UART1 (TX/RX + DMA) ←→ Raspberry Pi UART (GPIO 14/15)
- 共地：所有模块 GND 连接到电池负极

**Raspberry Pi 5 外设：**
- GPIO Pin 2/4 (5V) ← Mini560 #1 输出
- GPIO Pin 6 (GND) ← Mini560 #1 GND
- GPIO 14/15 (UART) ← STM32 UART1 (TX/RX 交叉)
- USB 口 A: LD06 激光雷达（UART-to-USB 适配板）
- USB 口 B: USB 摄像头

## 已确认引脚分配（STM32F103C8T6，2026-08-21）

### 为什么 4 个编码器全部走软件解码（2026-08-23 修正）

F103C8T6 只有 **TIM1/2/3/4 四个定时器**。TIM1 的 CH1/CH2 固定是 PA8/PA9（这颗芯片没有全重映射到其他引脚的选项），而 **PA8 是 NRF24L01 的 CE、PA9 是 USART1_TX（给树莓派通信）**——两个都不能挪，所以 TIM1 凑不出一路可用的硬件编码器。

> **本节此前写的"3 路硬件编码器 + 1 路软件解码"是错的。** 一个定时器的计数器要么按内部时钟自由计数产生 PWM，要么被外部正交信号驱动做编码器，**不能同时干这两件事**。TIM2/3/4 已经全部用来产生四路电机 PWM（TIM2 CH3/CH4、TIM3 CH3、TIM4 CH3），加上 TIM1 不可用，实际上**没有任何一个定时器能用于硬件编码器模式**。

结论：**四路编码器全部使用 GPIO 中断软件正交解码**。**2026-08-23 起改为 A 相双边沿触发（2 倍频）**，服务程序里比较 A、B 两相电平是否相同来判断方向——注意**不能只采样 B 相**，那在双边沿下会正负相消归零（`duty_sweep` 就踩过这个坑，见 2026-08-25 的修复提交）。这个中断频率对 64MHz 的 F103 毫无压力，实测四轮同时运行计数正常。**接线本身不受影响**——这是纯固件层面的修正。

EXTI 中断线是**按引脚编号**全芯片复用的（不分端口）：PA6、PB6、PC6 三者只能有一个占用 EXTI 线 6。FR 的 PA6/PA7 和 RL 的 PB6/PB7 编号正好撞车，所以 **RL 选 PB7（不是 PB6）作为中断脚**，四个中断脚落在 {0, 6, 7, 12} 上互不冲突。另一路只读电平、不挂中断，编号随便重复。

### 引脚表

| 用途 | 引脚 | 说明 |
|------|------|------|
| 电机 FL 编码器 A/B | PA0（中断）/ PA1（读电平） | EXTI0，软件正交解码 |
| 电机 FL PWM | PA2 | TIM2 CH3 |
| 电机 RR PWM | PA3 | TIM2 CH4（借用 TIM2 剩余通道） |
| 电机 FR 编码器 A/B | PA6（中断）/ PA7（读电平） | EXTI9_5，软件正交解码 |
| 电机 FR PWM | PB0 | TIM3 CH3 |
| 电机 RL 编码器 A/B | PB7（中断）/ PB6（读电平） | EXTI9_5；**中断脚用 PB7**，避开与 PA6 争用 EXTI 线 6 |
| 电机 RL PWM | PB8 | TIM4 CH3 |
| 电机 RR 编码器 A/B | PB12（中断）/ PB13（读电平） | EXTI15_10，软件正交解码 |
| USART1（树莓派通信） | PA9 (TX) / PA10 (RX) | 默认位置，不 remap |
| I2C2（MPU6050） | PB10 (SCL) / PB11 (SDA) | **用 I2C2 不用 I2C1**——I2C1 默认脚是 PB6/PB7，和 RL 编码器撞车 |
| NRF24L01 | PA8 (CE) / PA15 (CSN) / PB3 (SCK) / PB4 (MISO) / PB5 (MOSI) | 位翻转软件 SPI，见下方"NRF24L01 无线遥控接线"章节 |
| SWD 调试（ST-Link） | PA13 / PA14 | 保留别占，后面还要烧录/调试 |

编码器供电统一接 **3.3V**（不是 5V）：信号最终进 STM32 的 3.3V IO，编码器用 3.3V 供电时输出的高电平也是 3.3V，电平天然匹配。四个编码器的电源和地可以从面包板电源轨统一取。

### ⚠️ 哪些引脚是 5V 耐受的（改任何传感器供电前必读）

STM32F103 只有部分引脚 5V 耐受（datasheet 标 `FT`）。**ADC 复用脚一律不耐受。** 本项目四路编码器的引脚：

| 编码器 | 中断脚 / 读电平脚 | 5V 耐受 |
| --- | --- | --- |
| FL | PA0 / PA1 | ❌ **否**（ADC12_IN0 / IN1） |
| FR | PA6 / PA7 | ❌ **否**（ADC12_IN6 / IN7） |
| RL | PB7 / PB6 | ✅ 是（FT） |
| RR | PB12 / PB13 | ✅ 是（FT） |

**结论：编码器必须用 3.3V 供电，不能改 5V。** 5V 供电的编码器输出 5V 高电平，会直接灌进 PA0/PA1/PA6/PA7 这四个非耐受脚——和 2026-08-25 烧板那次的 4.8V 是同一类损伤。

如果将来要把编码器供电从板载 AMS1117 挪到独立模块（做故障隔离），**独立模块也必须是 3.3V**，并且**编码器的 GND 必须与 STM32 共地**，否则信号没有共同参考电平。

> ⚠️ **注意这 4 路编码器目前挂在 Blue Pill 板载的 AMS1117 上**，同一颗稳压器还要供 MCU 和 2 块 TB6612 的逻辑电源。2026-08-25 已有一块板的 AMS1117 击穿短路（详见 [power-system.md](power-system.md) 的故障记录）。**建议把编码器供电改由 Mini560 单独提供**，给板载稳压器减负。

### 编码器方向校准结果（2026-08-23 实测）

抬起底盘、40% 占空比跑 1.5 秒，四路计数：FL 631、FR 633、RL 640、RR 619，全部为正且车辆物理前进，四轮一致性约 3%。达成这个结果做了两处校准：

- **电机方向极性**：正占空比原本让整车**后退**（四个轮子一致），在 `motor_set_tim()` 里把每个电机的两个方向引脚按 (AIN2, AIN1) 顺序传入即修正，使"正占空比 = 前进"对所有上层调用都成立。
- **FL 编码器相位**：FL 计数方向与其余三个相反，**已通过对调 FL 编码器 A/B 两根线（PA0/PA1）修正**，不是软件取反。

### TB6612 方向控制：为什么需要 2 根线，不是 1 根

TB6612 每路电机的方向由 **两个输入脚**共同决定（真值表）：

| AIN1（或 BIN1） | AIN2（或 BIN2） | 电机状态 |
|------|------|---------|
| H | L | 正转 |
| L | H | 反转 |
| 两者相同 | 两者相同 | 刹车/滑行 |

麦轮车横移、原地转必须同时具备正转和反转，只接一根方向线做不到——要么只有"正转+刹车"，要么只有"反转+刹车"。固件里 `motor_set_tim()` 已改为接受两个方向引脚（`dir_pin_a`/`dir_pin_b`），驱动时二者电平互补（forward: A=H,B=L；reverse: A=L,B=H），见 `firmware/Core/Src/motor.c`。

若确认板子是裸露 AIN1/AIN2/BIN1/BIN2 引脚的经典 TB6612 模块（本项目就是这种），按下表接：

**TB6612 板 1（FL + FR）**

| 板子引脚 | 接到 |
|------|------|
| VM | 12V 电机总线 |
| VCC | 3.3V（STM32 板载 LDO，不要接 5V） |
| GND | 共地 |
| STBY | PB14（整体使能/急停用） |
| PWMA | PA2（TIM2_CH3，电机 FL） |
| AIN1 | PA4（FL 方向） |
| AIN2 | PA5（FL 方向，互补） |
| PWMB | PB0（TIM3_CH3，电机 FR） |
| BIN1 | PA11（FR 方向） |
| BIN2 | PA12（FR 方向，互补） |
| AO1/AO2 | 电机 FL 两端 |
| BO1/BO2 | 电机 FR 两端 |

**TB6612 板 2（RL + RR）**

| 板子引脚 | 接到 |
|------|------|
| VM | 12V 电机总线 |
| VCC | 3.3V |
| GND | 共地 |
| STBY | PC15（整体使能/急停用） |
| PWMA | PB8（TIM4_CH3，电机 RL） |
| AIN1 | PB1（RL 方向） |
| AIN2 | PB15（RL 方向，互补） |
| PWMB | PA3（TIM2_CH4，电机 RR） |
| BIN1 | PC13（RR 方向） |
| BIN2 | PC14（RR 方向，互补） |
| AO1/AO2 | 电机 RL 两端 |
| BO1/BO2 | 电机 RR 两端 |

> STBY 也可以两块板都直接接 3.3V 常使能，用软件急停（`motor_emergency_stop()` 把 PWM 占空比清零）代替硬件断使能。用 GPIO 控制 STBY 的好处是急停时能真正切断 H 桥输出，双保险。

### 编码器解码固件状态

四路 EXTI 软件正交解码**已合入生产代码** `firmware/Core/Src/encoder.c`（2026-08-23），原先的硬件定时器编码器模式已移除。

解码逻辑集中在单个入口 `encoder_on_edge(motor_id_t, bool b_level)`：真机由 EXTI 中断服务程序调用，主机单元测试和 SIL 直接调用同一个函数——这样解码逻辑可以脱离硬件测试，也保证 SIL 跑的是真实代码路径而不是绕过它写计数。

板级的 GPIO/EXTI 配置不属于 `encoder.c`，由各自的 board init 负责（参考 `firmware/Core/HW/encoder_port_check_main.c`）。

验证情况：主机单元测试 7 项（`firmware/Core/Test/test_encoder.c`，含方向、隔离、越界、复位、rad/s 换算）；真机 `encoder_port_check` 链接生产 `encoder.c` 实测 40% 占空比下 `encoder_get_speed_rads()` 返回 10.24–10.38 rad/s，与占空比扫频曲线预测的 10.25 rad/s 独立吻合。

## 历史参考：STM32F407VET6 候选方案（硬件选型阶段，已不采用）

以下 TIM 分配方案是硬件选型阶段针对 STM32F407VET6 候选板写的方案。**当前实际主控是 STM32F103C8T6，请使用上面"已确认引脚分配"章节，不要按这套接线。** 保留仅供对比参考。

### 核心设计原则

**关键约束：** 编码器模式会让定时器计数器由 TI1/TI2 边沿驱动；PWM 的周期和比较也依赖同一个计数器。因此不能把同一实例的 CH1/CH2 用作编码器，同时指望 CH3/CH4 生成固定频率电机 PWM。编码器和 PWM 必须使用不同的定时器实例。

（针对 STM32F407VET6：TIM2/3/4/5 分别采集四路编码器，TIM1/TIM8 提供四路 20 kHz PWM。此方案未采用。）

### 推荐分配方案

| 定时器 | 用途 | 通道 | 备注 |
|--------|------|------|------|
| TIM2 | 电机 FL 编码器 | CH1+CH2 | 32 位计数器，实际引脚待 CubeMX 确认 |
| TIM3 | 电机 FR 编码器 | CH1+CH2 | 16 位，软件处理回绕 |
| TIM4 | 电机 RL 编码器 | CH1+CH2 | 16 位，软件处理回绕 |
| TIM5 | 电机 RR 编码器 | CH1+CH2 | 32 位计数器 |
| TIM1 | FL/FR PWM | CH1+CH2 | 统一 20 kHz PWM 周期 |
| TIM8 | RL/RR PWM | CH1+CH2 | 统一 20 kHz PWM 周期 |

### PWM 驱动方案

- 使用 TIM1/TIM8 的输出比较通道产生固定 20 kHz PWM。
- TIM6/TIM7 没有外部 PWM 输出通道，不能直接拿来驱动 TB6612。
- 四路 PWM 统一周期，只改变 CCR 占空比；方向继续由 GPIO 控制。

### 实际应用

以 STM32F407VET6 为候选，**请在 STM32CubeMX 中：**
1. 配置 TIM2/3/4/5 为 **Encoder Mode（4x counting）**
2. 在相应通道添加中断处理溢出计数
3. 将 TIM1/TIM8 配成四路 PWM，目标频率 20 kHz
4. 在 `motor.h` 和 `encoder.h` 中更新对应的 GPIO 和定时器常数

- UART DMA 需配置接收和发送，推荐圆形缓冲区处理，避免溢出

## 供电接线（历史草案，已弃用）

### 电源拓扑

```
3S 锂电池 (11.1V 标称, 12.6V 满电)
  │
  ├─ XT60 接头 (防反接)
  │
  ├─ 10A 刀片式保险丝
  │
  ├─ 船型开关 (主电源开关)
  │
  ├──→ 【电机供电总线 (12V 直连)】
  │     ├─ 1000μF 25V 电解电容 ×2 (并联滤波，吸收堵转尖峰)
  │     ├─ TB6612 #1 VM 引脚 (电机 FL + FR)
  │     └─ TB6612 #2 VM 引脚 (电机 RL + RR)
  │
  ├──→ 【Mini560 降压模块 #1: 12V → 5.1V / 5A】
  │     ├─ Raspberry Pi 5 (GPIO Pin 2/4 供电)
  │     └─ LD06 激光雷达
  │
  └──→ 【Mini560 降压模块 #2: 12V → 5V / 3A】
        └─ STM32 开发板 (VIN 或 USB)
              └─ 板载 3.3V LDO → MPU6050 / VL53L0X / 其他 3.3V 传感器
```

| 设备 | 电压 | 典型电流 | 峰值电流 | 典型功率 |

| 树莓派 5 | 5V | 2.5A | 5A | 12W |
| STM32 开发板 | 5V→3.3V | 0.1A | 0.2A | 0.5W |
| LD06 激光雷达 | 5V | 0.35A | 0.5A | 2W |
| 电机 ×4 (正常运行) | 12V | 0.5A ×4 | — | 24W |
| 电机 ×4 (堵转尖峰) | 12V | — | 1.5A ×4 | 72W |
| USB 摄像头 | 5V | 0.2A | 0.3A | 1W |
| TB6612 逻辑电路 ×2 | 5V | 0.01A | — | 忽略 |
| MPU6050 + VL53L0X | 3.3V | 0.01A | — | 忽略 |
| **系统合计** | — | **~5A @ 12V** | **~8A @ 12V** | **~40W 典型** |

#### 为什么使用 2 个 Mini560 而不是 1 个

电机启动或堵转时，12V 总线会产生噪声尖峰（高频纹波和浪涌）。分离电源的好处：

1. **降低负载互扰**：Pi 与 MCU 分开稳压，减少 Pi 瞬态负载直接拉低 MCU 5 V 支路的概率。
2. **便于分别滤波和测量**：可以独立观察两路 5 V 纹波并按负载配置电容。
3. **独立稳压**：两路输出可独立调整，Pi 需要 5.1V（补偿线损），STM32 需要稳定 5V。

两路降压仍共用 3S 电池，不是电气隔离，也不是电源冗余。12 V 总线整体坍塌时两路都会掉电；安全策略不能依赖 MCU 在总线故障后继续运行。

TB6612 的 VM 绝对最大值接近 3S 满电电压，具体裕量必须按所购模块和数据手册确认，并测量制动/堵转尖峰；没有足够裕量时改用额定电压更高的驱动器。

#### TB6612 双电源设计

TB6612 有两组电源引脚，设计上已隔离电机噪声：

- **VM**（电机电源）：接 12V 总线，可串联 100Ω 磁珠进一步吸收高频噪声（可选）
- **VCC**（逻辑电源）：建议接 STM32 板载 3.3V，使输入阈值与 3.3V GPIO 匹配。VCC 本身不会反向给 GPIO 灌入 5V，但选择 5V 时必须重新核对输入高电平阈值，当前设计不采用。

这种设计天然隔离了电机和逻辑电路的电源，是行业标准做法。

## 首次上电检查清单

**重要：严格按照以下顺序操作，确保没有接线错误导致器件损伤。**

### 第一步：测试降压模块（**电池未连接，进行干测试**）

- [ ] 用恒流源或万用表测试 Mini560 #1 输出：应为 5.1V ±0.1V
- [ ] 用恒流源或万用表测试 Mini560 #2 输出：应为 5.0V ±0.1V
- [ ] 确认所有电解电容极性正确（长脚=+，短脚=-）
- [ ] 确认保险丝完好（用万用表欧姆档检测）

### 第二步：连接电池和启动 Raspberry Pi

- [ ] 用 XT60 连接电池到机器人主电源
- [ ] 打开主电源开关
- [ ] **观察 Mini560 指示灯**（如有）确认通电
- [ ] 连接 HDMI 和键盘到 Pi 5，确认系统启动
- [ ] 检查 LD06 激光雷达 USB 连接，运行 `ros2 topic echo /scan` 验证点云输出
- [ ] **不接电机的情况下，关键是验证 Pi 和 LD06 稳定工作**

### 第三步：连接 STM32，验证 MCU 通信

- [ ] 用 USB 线连接 STM32 开发板的 USB 接口（或通过 Mini560 #2 的 5V 供电）
- [ ] 在 Pi 上运行 `sudo dmesg | tail -20` 检查 UART 设备是否识别（通常 `/dev/ttyS0` 或 `/dev/ttyAMA0`）
- [ ] 运行串口监听工具（如 `picocom -b 115200 /dev/ttyS0`）
- [ ] 在 STM32 上发送心跳包（HEARTBEAT 帧，CMD_ID = 0x1F），验证 Pi 接收
- [ ] 确认 I2C 总线正常：`i2cdetect -y 1` 应显示 MPU6050 (0x68) 和 VL53L0X (0x29)

### 第四步：依次连接电机，空转测试

- [ ] **先连接 1 个电机** (例如 FL)，设置占空比 20%，空转 3 秒确认方向正确
- [ ] 从 STM32 读取编码器计数，确认变化（表示编码器接线正确）
- [ ] 逐个连接其他 3 个电机，重复上述测试
- [ ] 四个电机均成功运行后，进行 PID 调参（初始参数参考 `firmware/Core/Src/pid.c`）

### 第五步：全系统运行检查

- [ ] 启动 ROS2 驱动层：`ros2 launch mcr_bringup robot.launch.py`
- [ ] 验证底层反馈话题：`ros2 topic echo /odom_feedback` 应显示编码器计数、ToF、IMU、电池电压
- [ ] 启动遥控：`ros2 run teleop_twist_keyboard teleop_twist_keyboard`
- [ ] 在安全区域进行全向移动测试（前进、横移、旋转）
- [ ] 监控电机电流（如有电流表）：正常运行 0.3-0.8A/个，堵转峰值 <2A/个

### 电解电容安全检查

- [ ] **务必检查电解电容的极性（+/- 方向）**，接反会在通电瞬间爆炸
- [ ] 1000μF 25V 电容（12V 电机总线）：长脚接电池+，短脚接地
- [ ] 220μF 16V 电容（Mini560 输出）：长脚接 Mini560 输出 +，短脚接地
- [ ] 通电后监控电容温度（手指接近应无烫感），过热表示内部短路

### 故障排查

| 症状 | 可能原因 | 排查步骤 |
|------|---------|--------|
| Pi 启动后立即重启 | Mini560 #1 输出不稳定或接线虚接 | 用万用表测 5V 纹波，检查 XT60 接头接触 |
| STM32 无法通信 | UART 接线反向或波特率不匹配 | 用逻辑分析仪观察 TX/RX 波形，检查 CubeMX UART 配置 |
| 电机不转 | 方向 GPIO 故障、PWM 占空比为 0、或 TB6612 未使能 | 用万用表测 DIR 和 PWM 引脚电压，检查 STBY 引脚 |
| 编码器无反馈 | 编码器接线虚接或 TIM 配置错误 | 用万用表欧姆档测编码器 A/B 相电阻（通常 50-200Ω），用逻辑分析仪观察方波 |
| 电机堵转时 Pi 重启 | 电机噪声未隔离，12V 总线尖峰拉低 Mini560 输出 | 检查电解电容是否焊接，尝试并联更大容值（2200μF）或更高纹波电流的电容 |

## NRF24L01 无线遥控接线 (Wireless Remote)

机器人端 STM32 接 NRF24L01+ 接收模块,配合江协科技无线手柄实现全向遥控。详见 [docs/remote_control.md](remote_control.md)。

| NRF24L01 引脚 | STM32 GPIO | 说明 |
|------|---------|------|
| CE | PA8 | 片选使能 |
| CSN | PA15 | SPI 片选 (JTAG 释放后使用) |
| SCK | PB3 | SPI 时钟 (JTAG 释放后使用) |
| MISO | PB4 | SPI 数据入 (上拉输入) |
| MOSI | PB5 | SPI 数据出 |
| VCC | 3.3V | 必须 3.3V,不可接 5V |
| GND | GND | 共地 |

- 软件 SPI 驱动在 `firmware/Core/Src/nrf24l01.c`,引脚宏在文件顶部,换板子改宏 + `gpio_init()` 即可
- 引脚占用 PA15/PB3/PB4(默认 JTAG),初始化时已禁用 JTAG 释放
- 遥控启用:手柄按 K1;紧急停止:K9。手柄标称 10 Hz，车端失联 250 ms 自动急停（容忍正常抖动与单帧丢失）
