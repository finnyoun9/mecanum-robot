# 感知与定位：I2C、IMU、ToF、LD06 与 EKF

本文说明本地传感器、轮式里程计和ROS 2定位建图链。当前已完成传感器与首次移动建图闭合，但地图质量、EKF参数和Nav2尚未验收。

## 传感器职责

| 设备 | 接口/频率 | 系统职责 |
| --- | --- | --- |
| 四路编码器 | GPIO EXTI / 100 Hz控制读取 | 轮速与轮式里程计 |
| MPU6050 | I2C2 / 100 Hz | 角速度、加速度、Mahony姿态 |
| YB-MVV18 ToF | I2C2 / 20 Hz | 车头近距离停车 |
| SSD1306 OLED | I2C2 / 1 Hz | 本地诊断，不进入控制估计 |
| LD06 | Pi串口/USB / 约10 Hz | 360°激光扫描与SLAM |
| IMX219 | Pi CSI | 视觉实验，尚未进入运动控制闭环 |

## I2C2共享总线

PB10/PB11以100 kHz同时连接MPU6050、ToF和OLED。三者由SensorTask按不同频率访问，避免OLED刷新占用总线影响100 Hz IMU和20 Hz ToF。

OLED丝印`0x78`是包含R/W位的8位写地址，驱动使用7位`0x3C`。地址相同不代表控制器和显存寻址完全相同，屏幕兼容问题还需检查SSD1306/SH1106与页寻址方式。

I2C是有ACK的共享总线；一个设备拉住SDA、软复位后外设状态不一致或供电未完全复位，都可能影响同总线其他设备。项目曾通过整车断电恢复软复位后传感器挂零，说明需要总线恢复和独立电源状态诊断。

## MPU6050与Mahony AHRS

MPU6050以100 Hz采样六轴数据，Mahony算法用陀螺仪积分并用加速度方向修正roll/pitch，内部状态以四元数表示。

MPU6050没有磁力计，系统缺少绝对航向观测。静止gyro零偏会持续积分成yaw漂移；EKF只能融合已有观测，不能凭空生成绝对方向基准。

当前真机已证明四元数为单位长度、gyro非零且数据进入ODOM帧。gyro零偏校准和动态姿态精度仍未验收。

## ToF近距离安全测距

ToF用于车头近距离停车，不替代LD06的360°扫描。模块标称最小有效距离为15 mm；状态无效、超时和距离为0必须与真实近距离值区分。

曾出现距离只在257、514、771之间变化，即`0x0101/0x0202/0x0303`。对比burst和逐字节读取后，确认burst把低字节复制成高字节；改为分别读取状态、MSB和LSB后恢复连续毫米值。

安全层在100 mm触发停车，180 mm后允许解除，形成迟滞，避免目标停在阈值附近时每50 ms反复触发和解除。

## 轮式里程计

编码器计数先转换为四轮位置和速度，再通过麦轮正运动学得到车体`vx、vy、ω`，最后积分成平面位姿。

轮径、轴距、轮距、edges/圈和轮序都会直接缩放里程计。麦轮横移与转弯存在明显打滑，短距离直线正确不等于长轨迹建图不会累计误差。

## LD06与SLAM

LD06通过Pi侧驱动发布`/scan`，当前约10 Hz。静止测试中453个点有435个有效，逐点标准差中位数约8.1 mm，说明静止噪声不是当前地图扭曲的首要嫌疑。

SLAM Toolbox用激光扫描、TF和里程计做扫描匹配与占据栅格构建。项目已完成首次移动出图，但出现扇贝状边界和放射状毛刺，不能据此声称地图质量达标。

## EKF状态估计

`robot_localization`融合轮式里程计和IMU。过程噪声、观测协方差和输入字段选择决定各传感器的权重；错误协方差可能让滤波器过度相信漂移的yaw或打滑的轮式转角。

当前优先假设是gyro零偏、转弯打滑和EKF权重共同造成长轨迹误差。这仍是待验证假设，不是已证明的唯一根因。

## 推荐排查顺序

```text
静止传感器质量
→ 时间戳与发布频率
→ TF方向和坐标系
→ 轮径/轴距/edges标定
→ gyro bias
→ EKF字段和协方差
→ 重复固定轨迹
→ 最后再调SLAM扫描匹配参数
```

先证明输入，再调整上层算法。直接修改SLAM参数可能暂时改善图像，但会掩盖时钟、TF、里程计或IMU的根因。

## 当前边界

没有磁力计或其他绝对航向观测时，单靠MPU6050不能长期约束yaw。激光扫描匹配可以提供环境约束，但依赖场景结构、运动速度和初始里程计质量。

IMX219与YOLOv8n已有独立CPU推理基线，但检测结果尚未进入机器人行为、安全约束或导航闭环。
