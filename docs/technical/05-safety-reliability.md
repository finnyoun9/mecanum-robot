# 安全与可靠性：默认停车、故障锁存与控制权仲裁

本文描述机器人在上电、失联、近障、堵转和多控制源竞争时如何进入安全状态。它是工程安全策略，不等同于经过认证的功能安全系统。

## 安全目标

1. 上电和软件异常时默认不驱动电机。
2. 显式急停不能被普通运动命令自动解除。
3. 失联、近障和堵转具有不同触发与恢复语义。
4. Pi和无线手柄不能同时无规则修改四轮目标。
5. 故障必须可观察、可复现、可验证恢复路径。

## 为什么不能只用一个布尔量

“停止”可能来自用户K9、通信超时、ToF、堵转、上电锁或控制器停用。它们的危险程度和解除条件不同；若全部压成一个`emergency_stop`，新命令可能错误地释放仍然存在的硬件故障。

| 触发源 | 动作 | 解除规则 |
| --- | --- | --- |
| 上电安全锁 | STBY关闭、目标清零 | 有效控制链和允许启动条件成立 |
| K9显式急停 | 立即停车并保持 | 明确的用户恢复动作，不由普通速度命令释放 |
| 通信超时 | 目标清零、停车 | 链路恢复且收到有效运动命令 |
| ToF近障 | 禁止继续向障碍物运动 | 退到180 mm外后按规则解除 |
| 电机堵转 | 关闭驱动并锁存故障 | 检查机械/线束后由K10或明确命令清除 |

## 通信看门狗

手柄标称约100 ms发送一次，项目使用250 ms超时，容忍调度抖动和单帧丢失。超时值是配置阈值，不是仪器测得的精确停车延迟。

通信超时属于可恢复链路故障。若新命令不能解除，机器人恢复通信后永远无法运动；若任何命令都能解除，则显式急停和堵转保护会失效。因此恢复逻辑必须区分故障来源。

## ToF停车与迟滞

距离小于100 mm时触发近障停车，超过180 mm后才清除。两个阈值形成迟滞，避免传感器噪声使状态在临界值附近来回切换。

近障状态仍允许机器人向后退离障碍物，但不能继续向前挤压目标。这比无条件关闭所有方向更利于脱困，也要求控制层知道车体运动方向。

## 堵转检测与锁存

当输出绝对值超过150、实测速度仍低于1.0 rad/s并持续500 ms时，对应车轮被判定为堵转。阈值来源于启动死区和真机速度曲线，不是任意常数。

堵转可能代表卡住、断线、电机损坏或编码器故障。故障发生后必须锁存，普通deadman恢复不能重新驱动问题电机；检查后通过K10或`CMD_CLEAR_MOTOR_FAULT`显式清除。

## 多控制源仲裁

Pi控制频率可达100 Hz，手柄约10 Hz。如果双方直接写`target_w[]`，即使Pi只发送零速度，也会频繁覆盖用户摇杆，表现为发飘、不跟手或刚动就停。

当前策略是手柄优先租约：RemoteTask每收到包就刷新`remote_active`；租约有效时，STM32忽略Pi的轮速赋值。250 ms内没有新手柄包后，租约过期，Pi重新获得控制权。

Pi侧同时只在命令变化或保活到期时发送，减少无意义总线流量。但降低发送频率不是完整仲裁，真正的安全边界仍在STM32控制权状态中。

## TX背压与降级

STM32 TX DMA繁忙时丢弃新的遥测帧，避免阻塞控制任务；Pi非阻塞写遇到短暂`EAGAIN`时做有界重试，不立即停用整个硬件组件。

若写失败持续约1秒，Pi侧才升级为链路错误。独立于此，STM32通信看门狗会更早停止电机，因此Linux上层故障不会成为唯一安全屏障。

## 电源与硬件保护

电机电源、Pi和STM32必须共地，但应避免多路电源互相反灌。历史上AMS1117击穿导致约4.8 V进入MCU供电域，说明每次改供电或换板都应先空载测量电压，再接入主控和外设。

完整电源拓扑、Mini560分工和上电顺序由[供电方案](../power-system.md)维护。接线电压容限和首次上电检查由[接线指南](../wiring.md)维护。

## 电池监测边界

电池ADC方案使用100 kΩ/27 kΩ分压，将12.6 V压到约2.68 V，并包含采样和OLED显示代码。当前状态是`[CODE][HOST][PENDING-HW]`：尚未改线、烧录和用万用表校准。

电池百分比不能只按电压线性映射。负载压降、电芯差异、温度和放电曲线都会影响估算；当前功能更适合作为电压提示，不应声称精确SOC。

## 当前边界

项目安全机制是面向个人机器人原型的风险控制，没有完成ISO 13849、IEC 61508等标准分析，也没有独立硬件急停回路、电流传感器或双通道冗余。

K9、失联、K10等功能已做基础真机验收，但精确响应延迟、复杂无线干扰、长期误报和极端电源条件仍未量化。
